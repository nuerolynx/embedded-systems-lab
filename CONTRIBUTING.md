# Contributing

Focused improvements, documentation corrections, and reproducible bug reports are welcome.

## Before opening a pull request

1. Keep the change scoped to one project or one repository-wide concern.
2. Never include credentials, access-card UIDs, private endpoints, personal data, or generated build output.
3. Document the board, board-package version, library versions, wiring changes, and test result.
4. Preserve safe defaults. Do not disable brownout protection or bypass a safety interlock to hide a hardware problem.
5. Update the project README when behavior, dependencies, pin assignments, or configuration steps change.

Pull requests should explain what changed, why it changed, how it was tested, and what remains unverified on physical hardware.
